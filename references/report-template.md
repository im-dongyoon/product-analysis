# 원고 틀

보고서는 `docs/` 원고 여러 개를 빌드해 만든다(SKILL.md 6절). 해당 없는 절은 지운다. 못 본 값은 '미확인'. 모든 항목에 [사실]/[추정]/[미확인]/[2차].

## docs/00-overview.md

```markdown
# <서비스명> 서비스 분석 (<YYYY-MM-DD> 확인)

한 줄 요약: <누구에게 무엇을 어떻게 해 주고, 어디서 돈을 버는지>

> 재현 시 문구·이미지·브랜드·로고는 바꿔서 쓸 것. 이 문서의 원문 인용은 분석 기록용이다.

표기: [사실] 화면·응답·파일로 확인 / [추정] 근거 적음 / [미확인] / [2차] 2차 자료.

## 0. 분석 범위
| 항목 | 내용 |
|-|-|
| 대상 | URL, 앱 |
| 본 범위 | 비로그인 / 로그인 / 유료, PC / 모바일, 직접 써 본 흐름 |
| 못 본 범위 | 무엇, 이유 |
| 남긴 흔적 | 만든 계정·데이터 (결제·제출 없음 여부) |
| 따로 받은 질문 | 있으면 |

산출물 (이 폴더 하나):
- `index.html` 보고서 / `docs/` 원고 목록 / `captures/` 하위 폴더별 장수 / `data/` 하위 폴더 설명

## 1. 질문별 답 (따로 받은 질문이 있을 때만)
| 질문 | 판정 (참/거짓/부분참/미확인) | 답 | 근거 |

## 2. 회사·사업 요약 (상세: 01-business)
운영사, 투자, 요금 원문, 돈 버는 지점

## 3. 시스템 구조 (재현용 설계도)
| 층 | 이 서비스가 쓰는 것 | 근거 |
(프런트 / 호스팅 / API / 인증 / DB / 실시간 / AI·외부 엔진 / 결제 / 분석·마케팅 / 메일 / 하위 도메인)

## 4. 핵심 데이터 구조
mermaid erDiagram + 핵심 엔티티 필드(실제 응답에서 본 것 우선)

## 5. 핵심 흐름 파이프라인 (실측)
| 단계 | 화면 행동 | API | 진행 문구 원문 | 비용·한도 실측 |

## 6. 화면·흐름 규모
| 구분 | 개수 | 출처 |

## 7. 서로 다른 출처가 엇갈린 곳 (판정)
| 항목 | 출처 1 | 출처 2 | 판정 |

## 8. 재현 점검표
| 영역 | 채운 것 | 빈 곳 | 상태 |
- 화면: 완전 N / 전체 M, 흐름: 끝까지 N / M, API: 실측 N / 목록 M

## 9. 확인 못 한 것
| 무엇 | 이유 | 보려면 필요한 것 |

## 10. 결정 필요 사항
| 결정할 내용 | 선택지 | 추천안과 근거 | 답이 늦으면 생기는 일 |
```
